# Apple-style Native Presentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for inline implementation, preserving Jacob's earlier preference for one independent final review. Use checkbox syntax to track progress.

**Goal:** Give the installed Public 5 iPhone app genuine Liquid Glass navigation, native sheets and tactile feedback while preserving its existing workflows.

**Architecture:** One persistent Capacitor web view under a native container. React owns authentication, routing, unread data and business UI; a typed local plugin supplies sanitized presentation state to native controls and delivers allowlisted navigation actions back to React.

**Tech Stack:** React 19, TypeScript, Capacitor 8.5.3, UIKit/SwiftUI, Xcode 27.2, Node 24, npm 11.5.2.

**Spec:** `docs/superpowers/specs/2026-10-10-ios-glass-design.md`, approved by Jacob on October 10, 2026. Jacob subsequently asked to move ahead with Liquid Glass and leave checklist behavior unchanged. Photo uploads work by his report; text-field zoom remains a native layout acceptance case.

## Global Constraints

- Work locally in `roadshow-ios-personal`, branch `feat/ios-personal-public`; current design commit `d8b2fb3`. Preserve the existing uncommitted Xcode signing edits.
- Keep one web view, existing Public 5 backend/configuration guards, role/active-account authorization and free Personal Team signing.
- Keep bundle ID `com.jacobabbott.roadshowdriver`, deployment minimum iOS 15, scene forwarding and existing login/session behavior.
- Use system Liquid Glass on supported iOS, conventional system-material fallback on older iOS, and opaque surfaces for Reduce Transparency.
- Device-local System/Light/Dark preference defaults to System; accent is green. No account appearance writes from native presentation choices.
- No push, local reminders, widgets, Live Activities, new capabilities, paid services, backend changes, deployment, merge, or remote push of commits.
- No credentials or business contents in native bridge payloads. No production fixtures or checklist-permission changes.
- Required checks: unit/UI/native pipeline tests, web build, lint with only the existing three warnings, guarded native sync and unsigned iOS compilation. Actual device results must be distinguished from mocks.

## Review Focus

1. App resumes with stale authenticated native controls: hide chrome until fresh verified state, with regression coverage in Task 2.
2. Native navigation replaces the web view or loses input: identity/state continuity and nested-route tests in Tasks 1–2 and device acceptance in Task 4.
3. Native controls obstruct keyboard or web modal: explicit measured layout ownership and modal tests in Tasks 2–3.
4. Native appearance leaks into web/account settings: local-only persistence and zero account-update tests in Task 3.
5. Failed bridge leaves two bars or none: readiness/disconnect fallback tests in Task 2 and device acceptance in Task 4.
