# Personal iPhone build — Public 5

This local Capacitor app packages Public 5 from `950a2628` and uses your existing
Roadshow account and live data. It is not TestFlight and needs a Personal Team
rebuild/reinstall after seven days. Preserve the bundle ID and reinstall over the
app; deleting it also deletes local session/settings. It needs internet access.
Notifications inside the app work as on the website; closed-app remote push is
not included. Recovery opens the public website in the device's browser, then
you return to this app to sign in.

## Build

Use Node 24 and npm 11.5.2. This checkout has the latter installed at
`work/toolchain/node_modules/npm/bin/npm-cli.js` without changing global npm.
Install locked dependencies with that npm's `ci` command on a fresh checkout.

Create ignored `.env.ios.local` with `VITE_SUPABASE_URL` set to
`https://myraoovepjwhkafzdppq.supabase.co`, the matching browser-safe anon or
publishable `VITE_SUPABASE_ANON_KEY`, `VITE_RELEASE_CHANNEL=public` and
`VITE_RELEASE_VERSION=5`. Never supply a service-role or secret key.
The current checkout's client values were obtained from the public website's
published assets; they are not committed. Both build and startup reject a wrong
origin/channel/version or obviously privileged key. This validation is a
configuration guard, not cryptographic verification of a client key.

```sh
npm run ios:sync
npm run ios:open
```

Always run `ios:sync` before opening/building changed assets. It validates,
cleans `dist-ios`, rebuilds, and only syncs after success. Direct `cap sync` is
not the supported build procedure. Ordinary `npm run build` still targets `dist`.

The iOS project is `ios/App/App.xcodeproj`. Xcode 27 requires the scene lifecycle
already generated by Capacitor 8.5.3. SPM dependencies and their resolved versions
are recorded in Git; generated web assets and signing state are ignored.

## User-assisted installation

Use official Xcode 27.2 beta 2 (27B5028f) for this phone's iOS 27.2.
The current installed app is `/Users/jacoba/Downloads/Xcode-beta.app`.
Its location can change; use the correct path in `DEVELOPER_DIR` when invoking
command-line builds rather than changing global tool selection unnecessarily.

1. Open the project in Xcode and connect/unlock your iPhone 17 Pro.
2. Handle Apple sign-in, any agreements, device trust and Developer Mode prompts
   yourself. No paid enrollment is required.
3. In the App target's Signing & Capabilities, select your Personal Team and
   authorize automatic signing yourself. The committed project uses manual
   signing with no team so merely opening it does not request credentials.
4. Choose the iPhone destination and Run. Xcode may ask permission to generate a
   development certificate/profile or access a signing key; these are your
   security decisions. Do not enable push or other paid capabilities.
5. Sign in yourself. App actions now affect live Roadshow records. Use normal
   work; automated tests must not create production fixtures.
6. Within seven days, run `ios:sync` if code/config changed, then Run from Xcode
   again with the same bundle ID. No paid distribution or public deployment.
